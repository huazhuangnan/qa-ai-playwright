# 项目模板管理

升级或修复前会再次核对项目所有权记录。规划期间记录发生变化时，操作停止并要求重试。

项目记录的 `last_successful_init` 保存最近一次成功初始化请求的浏览器选项，以及是否请求浏览器系统依赖。浏览器选项为 `none` 时，系统依赖请求记录为 `false`。该记录不表示已安装浏览器清单。初始化失败时保留上次成功记录。旧项目没有此字段也可继续使用。

`qa project plan <目录>` 只读比较模板和项目的受管文件。
不提供自动模板升级。`qa project plan <目录>` 只输出差异和冲突。维护者人工更新模板文件后，再执行 `qa project check <目录>` 和 `qa project plan <目录>` 复核。
`qa project repair <目录>` 只恢复缺失的受管模板文件。当前模板文件必须与项目记录的哈希一致。若模板已变化，修复停止并提示维护者人工处理。它不覆盖已有文件，也不改变模板版本记录。
`qa project snapshots <目录>` 列出项目升级前的快照标识。`qa project rollback <目录> <快照标识>` 恢复快照覆盖的受管文件及项目记录。

快照用于人工变更前备份和回滚。回滚先检查全部受影响文件和项目记录。快照保存在环境目录内，不包含依赖目录。

升级保留已有受管文件的权限。快照记录文件权限，回滚时恢复。新文件采用模板文件权限。

模板检测报告未修改的受管文件、可新增文件和冲突。CLI 不自动写入模板文件、安装依赖或运行迁移。维护者人工应用变更后，再按项目语言指南重新安装依赖并检查。
Python 的 `requirements.in` 需要改变且依赖锁基线不匹配时，检测会停止并提示人工更新依赖锁。依赖锁更新由维护者使用项目原有工具完成，再执行项目检查。
TypeScript 的 `package.json` 或 `pnpm-lock.yaml` 变化后，依赖更新由维护者使用项目原有工具完成，再执行项目检查。
普通模板目录不作为独立资产登记。卸载删除符合记录的模板文件，但保留目录和其中的其他内容。
卸载保留发生修改的受管文件时返回非零退出码，并保留其所有权记录。依赖目录及未跟踪文件默认保留，不影响退出码。
人工变更中断后，再次执行 `project plan` 检查状态。若文件和记录不一致，命令保留文件并报告冲突。
