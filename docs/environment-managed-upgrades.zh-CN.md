# 环境内 uv 变更检测与恢复

[使用人员](../README.md) | **维护人员**

适用对象：维护人员。阅读顺序：先看检测边界，再看快照、回滚和失败处理。本页描述维护动作，不是日常初始化步骤。

`env plan uv` 检查环境内已安装的 uv、版本记录和当前配置目标。它只读取文件并查询 uv 版本。
初始化下载并校验 uv 后记录可执行文件的 SHA256。升级或替换前必须与该记录一致。
新 uv 校验成功后立即保存哈希。后续初始化步骤失败时，重试会先校验该记录。
CLI 不执行隔离安装或自动替换。快照只用于维护者人工变更前的备份和回滚。
旧环境缺少哈希记录时不自动接管或覆盖现有文件。先备份并自行移走旧 uv，再执行原语言的 `env init` 重新安装和建立记录。
哈希不匹配时保留文件。先核对和备份本地修改，再自行处理后重新初始化。
不提供自动升级。`env plan uv` 只检测当前版本、目标版本、所有权哈希和快照状态。需要升级时由维护者按计划人工替换 uv，再执行 `env check`。CLI 不下载、安装或替换新版本。
已有 uv 与目标版本不一致时，`env init` 和 `env repair` 会保留它并提示维护者人工处理。它们不会直接替换已安装的 uv。
`env snapshots uv` 只读列出快照标识、阶段和版本。
`env rollback <快照标识>` 仅恢复该快照对应的 uv。当前文件、版本记录或快照不匹配时停止。
命令只处理当前环境 `bootstrap/uv`，不改动 Python 项目或共享软件。

快照位于环境 `bootstrap/uv-snapshots/`。快照记录原始状态和恢复阶段。
未完成首次快照写入的目录在列表中显示为 `incomplete`。此时原始 uv 尚未替换。
快照只用于人工变更前备份和变更后的回滚。
遇到快照以外的文件或状态变更时，回滚停止并保留数据。
操作锁记录主机和进程标识。确认原进程已不存在时可自动回收。无法确认时保留锁并报告路径。
共享 Node、Bun、pnpm、浏览器工具和 MCP 包可能被多个环境使用。旧记录不足以确认全部引用和原始文件。不要以环境升级替换这些软件。应通过软件原有工具管理，或在具备完整所有权和跨环境引用记录后再实施隔离升级。
