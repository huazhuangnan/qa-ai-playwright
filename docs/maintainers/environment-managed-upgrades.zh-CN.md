# 环境内 uv 变更检测与恢复

[使用文档](../users/README.md) | [维护文档](README.md)

适用对象：维护人员。先看检测边界，再看快照、回滚和失败处理。

## 检测与升级

- `env plan uv` 只读检查已安装版本、目标版本、所有权哈希和快照状态。
- 初始化下载并校验 uv 后立即记录 SHA256。升级或替换前必须核对该记录。后续初始化失败时，重试会先校验哈希。
- CLI 不提供隔离安装或自动升级。需要升级时，维护者按计划人工替换 uv，再执行 `env check`。
- 已有版本与目标不一致时，`env init` 和 `env repair` 保留现有 uv，并提示人工处理。
- uv 记录缺少哈希或哈希不一致时拒绝使用。移走现有文件后重新执行 `env init`。
- 哈希不匹配时保留文件。先核对并备份本地修改，再处理文件和重新初始化。

命令只处理当前环境的 `bootstrap/uv`。它们不改动 Python 项目或共享软件。

## 快照与回滚

- 快照位于 `bootstrap/uv-snapshots/`，记录原始状态和恢复阶段。它用于人工变更前备份和变更后的回滚。
- `env snapshots uv` 只读列出快照标识、阶段和版本。首次快照尚未写完时显示 `incomplete`，原始 uv 此时尚未替换。
- `env rollback <快照标识>` 仅恢复该快照对应的 uv。当前文件、版本记录或快照不匹配时停止。
- 快照以外的文件或状态发生变化时，回滚停止并保留数据。
- 操作锁记录主机和进程标识。确认原进程不存在时可自动回收。无法确认时保留锁并报告路径。

共享 Node、Bun、pnpm、浏览器工具和 MCP 包可能被多个环境使用。旧记录不足以确认全部引用和原始文件。不要通过环境升级替换这些软件。

使用软件原有工具管理共享软件。隔离升级需要完整的所有权和跨环境引用记录。
