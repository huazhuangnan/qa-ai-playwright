# 项目模板管理

[使用文档](../users/README.md) | [维护文档](README.md)

适用对象：维护人员。阅读顺序：先看所有权和冲突保护，再看计划、修复、快照和回滚。本页描述维护动作，不是项目使用向导。

升级或修复前会再次核对项目所有权记录。规划期间记录发生变化时，操作停止并要求重试。

项目记录的 `last_successful_init` 保存最近一次成功初始化请求的浏览器选项，以及是否请求浏览器系统依赖。浏览器选项为 `none` 时，系统依赖请求记录为 `false`。该记录不表示已安装浏览器清单。初始化失败时保留上次成功记录。

## 命令与保护

- `qa project plan <目录>` 只读比较受管文件，输出差异和冲突。CLI 不提供自动模板升级。
- `qa project repair <目录>` 只恢复缺失的受管模板文件。模板哈希必须与项目记录一致。模板变化时停止并提示人工处理。修复不覆盖已有文件，也不改变模板版本记录。
- `qa project snapshots <目录>` 列出升级前的快照标识。
- `qa project rollback <目录> <快照标识>` 恢复快照覆盖的受管文件和项目记录。

维护者人工更新模板后，执行 `qa project check <目录>` 和 `qa project plan <目录>` 复核。

快照用于人工变更前备份和回滚。回滚先检查全部受影响文件和项目记录。快照保存在环境目录内，不包含依赖目录。

升级保留已有受管文件的权限。快照记录文件权限，回滚时恢复。新文件采用模板文件权限。

## 依赖与卸载

模板检测报告未修改的受管文件、可新增文件和冲突。CLI 不自动写入模板文件、安装依赖或运行迁移。人工应用变更后，按语言指南重新安装依赖并检查。

- Python：`requirements.in` 需要改变且依赖锁基线不匹配时，检测停止并提示人工更新。使用项目原有工具更新锁，再执行项目检查。
- TypeScript：`package.json` 或 `pnpm-lock.yaml` 变化后，使用项目原有工具更新依赖，再执行项目检查。
- 卸载：删除符合记录的模板文件，保留普通目录及其他内容。修改过的受管文件及其所有权记录会保留，并返回非零退出码。依赖目录和未跟踪文件默认保留，不影响退出码。
- 中断恢复：人工变更中断后，重新执行 `project plan`。文件和记录不一致时，命令保留文件并报告冲突。
