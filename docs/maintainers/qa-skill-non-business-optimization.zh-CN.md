# QA Skill 非业务优化升级

[使用文档](../users/README.md) | [维护文档](README.md)

## 文档定位

本方案只处理 QA Skill、模板、报告、证据和执行治理。
业务规则、业务字段和项目专属验收条件继续放在项目 `AGENTS.md`、项目 Skill 或项目 QA 文档中。

目标是减少规则漂移、降低人工判断、提高结果可比较性，并让 Skill 的要求能够被检查和持续维护。

## 当前基线

当前仓库已经具备以下基础：

| 领域 | 已有能力 | 主要缺口 |
| --- | --- | --- |
| Skill 入口 | `qa-core` 统一入口，`qa-setup` 管理环境 | 版本、来源和兼容关系仍需集中展示 |
| 执行边界 | 已定义输入、环境、敏感信息、清理和证据规则 | 关键规则多数依赖人工遵守 |
| 结果判定 | 已区分首次通过、重试后通过、失败、跳过、未执行 | 状态枚举和 CLI、报告之间还需固定映射 |
| 失败分析 | 已有环境、产品、测试实现、数据污染等分类 | 缺少统一主因、次因和门禁处理协议 |
| 报告模板 | 已有执行报告、缺陷报告和追踪 ID | 证据目录、保留期限和模板版本校验不统一 |
| Playwright | 已有 locator、认证、trace、重试等规则 | 配置策略分散，缺少机器检查和环境级默认值 |
| 项目边界 | 已明确通用 Skill 不承载业务规则 | 需要在升级流程中增加边界检查 |

## 升级目标

1. Skill 版本、来源、兼容的 CLI 版本和更新时间可追溯。
2. 关键质量要求有稳定的机器检查入口。
3. 测试结果、失败分类和证据结构可以跨项目比较。
4. 公共规则只有一个权威来源，专业 reference 通过链接复用。
5. 已获得授权的普通任务可以连续执行，只有高风险写入或关键缺口才暂停。
6. 升级不会把 EasyLoon 等项目业务规则回灌到通用 Skill。

## 分批升级计划

### P0：先稳定公共契约

| 项目 | 交付内容 | 主要落点 | 验收标准 |
| --- | --- | --- | --- |
| 版本与来源 | 给 `qa-core`、`qa-setup` 增加来源、兼容 CLI、更新时间和变更摘要字段 | `SKILL.md`、版本记录、锁记录 | 项目安装记录、Skill 元数据和交付包版本一致 |
| 公共规则收敛 | 明确 `common-workflow.md` 为执行边界唯一来源，其他 reference 只补充领域规则 | `qa-core/references/` | 相同规则只保留一份；链接可解析 |
| 结果状态 | 固定 `passed / failed / flaky / skipped / blocked / unexecuted`，定义 CLI、报告和对话的映射 | `common-workflow.md`、`triage.md`、报告模板 | 跳过和未执行不计入覆盖；重试后通过固定为 `flaky` |
| 质量门禁 | 增加只读检查，覆盖 `.only`、`any`、固定等待、危险证据、未登记环境变量和认证文件 | QA CLI 或维护检查脚本 | 检查结果有明确退出码；不能以跳过取得成功 |

### P1：统一执行和证据模型

| 项目 | 交付内容 | 主要落点 | 验收标准 |
| --- | --- | --- | --- |
| 测试层级矩阵 | 固定 unit、functional、api、integration、e2e、smoke、regression 的目录、标签、依赖和证据 | `qa-core` reference、模板 | 一个用例有唯一主层级和可解释标签 |
| Fixture 生命周期 | 统一创建、登记、清理、清理失败和失败保留字段 | TypeScript/Python 模板、公共执行边界 | 数据按 LIFO 清理；原错误与清理错误分别保留 |
| 认证状态治理 | 为 `storageState` 增加来源、角色、环境和失效诊断约定 | 模板、`qa-setup`、执行报告 | 能区分过期、角色错配和服务端会话失效 |
| 证据治理 | 统一 `RUN-ID/EVIDENCE-ID` 目录、脱敏摘要、原始 trace 保留策略和访问说明 | 执行报告模板、维护文档 | 报告只引用脱敏证据；敏感文件不会进入公共产出 |
| Playwright 配置 | 固定本地与 CI 的 retries、trace、截图、视频、workers、reporter 默认策略 | TypeScript 模板及对应文档 | CI 失败可诊断；默认不为所有运行保存完整 trace |
| Locator 审查 | 固定优先级 `role > label > test id > text > CSS/XPath`，例外记录原因 | Web reference、代码检查 | 例外可追踪；禁止深层结构选择器作为默认方案 |

### P2：降低维护成本

| 项目 | 交付内容 | 主要落点 | 验收标准 |
| --- | --- | --- | --- |
| 失败分类 | 固定主因枚举：环境、依赖、产品、测试实现、数据污染、顺序污染、基础设施、待确认 | `triage.md`、报告模板 | 每次失败有一个主因，可选次因 |
| 影响分析 | 提供变更来源、受影响测试层、失效用例、补测范围和未覆盖项模板 | 维护文档、QA 模板 | 需求、契约、代码、环境或数据变化可追踪 |
| 执行成本 | 规定“目标用例 → 相关目录 → 标签回归 → 全量回归”的升级路径 | `common-workflow.md` | 默认不直接运行无关全量套件 |
| 并行安全 | 增加数据、端口、文件、mock、认证状态和数据库锁的隔离检查 | 模板、维护检查 | 并行运行具备可验证的隔离条件 |
| 工具路由 | 用一张决策表区分源码、API、Playwright、浏览器探索、原生桌面和环境管理 | `external-skills.md` 或新增 reference | 同一任务不会因工具边界重复执行 |
| 生成流程 | 普通授权任务直接执行；高风险写入、真实数据、凭证或关键预期缺失时才暂停 | `qa-core/SKILL.md` | 不因形式化确认阻塞已明确任务 |

## 机器检查建议

检查器先做只读扫描，输出文件、规则编号、严重程度、建议和退出码。
建议至少覆盖：

- 测试代码中的 `.only`、`test.only`、`describe.only`、`waitForTimeout`、无说明的 `force` 和宽泛 `any`。
- 被提交的 `.env`、认证状态、Cookie、私钥、trace、视频和未脱敏截图。
- 未登记的环境变量、未锁定的依赖和与 Skill 元数据不一致的版本。
- 报告中的状态、统计和证据引用是否满足互斥计数。
- 项目 Skill 是否包含业务项目专属规则。

检查器只报告能由文件、配置或运行结果证明的事实。
它不把静态检查结果当作业务测试通过，也不替代真实环境验证。

## 统一输出契约

所有执行报告至少包含：

| 字段 | 要求 |
| --- | --- |
| 范围 | 计划、标签、浏览器、环境和构建版本 |
| 命令 | 实际命令、工作目录和退出码 |
| 结果 | 六种固定状态的互斥统计 |
| 证据 | `RUN-ID`、`EVIDENCE-ID` 和脱敏路径 |
| 失败 | 主因、关联用例、缺陷或阻塞原因 |
| 清理 | 数据、进程、浏览器和残留状态 |
| 限制 | 未执行项、未验证环境和剩余风险 |
| 版本 | Skill、CLI、模板和依赖锁版本 |

对话交付与文件报告必须使用同一统计口径。
局部通过不能推导整体 E2E 通过。

## 边界与禁止事项

- 不把 EasyLoon、PYVIO 或其他项目的业务资格、字段和流程写入通用 Skill。
- 不用增加重试、删除断言或扩大超时掩盖失败。
- 不把浏览器探索、静态扫描或 CLI 自检描述为业务验收通过。
- 不因一次重试通过清除 flaky 记录。
- 不在没有授权和脱敏条件时读取、保存或分享真实凭证与客户数据。
- 不为一次性需求新增独立 Skill；优先补充现有 reference 或模板。

## 实施顺序与验收门槛

建议按以下顺序落地：

1. 先更新 `common-workflow.md`、`triage.md` 和执行报告模板，固定公共契约。
2. 再更新 `qa-core`、`qa-setup` 的元数据、路由和版本记录。
3. 增加只读质量门禁，并在 CI 中先以报告模式运行。
4. 更新 TypeScript/Python 模板，再将门禁切换为阻断模式。
5. 用一个无业务规则的示例项目完成安装、升级、执行、失败和回滚验证。

每一批升级完成后必须满足：

- 文档链接、Skill 路由和模板引用可解析。
- 维护测试、模板检查和相关 CLI 检查通过。
- 未执行的平台、真实频道和外部服务仍明确标记为未验证。
- `docs/maintainers/version-history.zh-CN.md` 记录未发布变化。
- 不提交业务项目中的局部规则或真实敏感数据。

## 本轮结论

本轮建议优先实施 P0，再实施 P1。
P2 属于降低长期维护成本的优化，可在公共契约稳定后按维护窗口推进。
后续代码变更应以本文为升级基线，并在每次发布时回填实际完成项、未完成项和验证范围。
