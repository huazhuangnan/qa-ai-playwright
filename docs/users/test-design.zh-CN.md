# 测试设计与生成

[使用文档](README.md) | [维护文档](https://github.com/huazhuangnan/qa-ai-playwright/blob/main/docs/maintainers/README.md)

本页负责测试场景选择、生成代码质量和专项边界。整体流程见[AI 测试模型](ai-testing-model.zh-CN.md)。

## 判断边界

通用基线和扩展目录只提供思考框架，不要求机械套用。

- 根据业务目标、源码、契约、页面观察和风险判断适用性。
- 资料明确时形成正式用例。
- 资料冲突时并列来源并标待确认。
- 资料不足时只提交候选建议。
- 排除无关场景，并说明不采用原因。
- 默认输出 5 至 10 个高价值场景。
- 只有高风险或用户要求时才扩大清单。

## 通用基线

| 维度 | 默认检查 |
| --- | --- |
| 入口 | 前置状态、入口可达、刷新和返回 |
| 主流程 | 最小合法路径和必要业务结果 |
| 输入 | 必填、空值、格式、长度和边界 |
| 权限 | 未登录、角色和资源归属 |
| 状态 | 合法转换、非法转换和不可逆结果 |
| 持久化 | 数据、关联记录和审计是否真实变化 |
| 失败 | 空状态、依赖失败、重试和用户恢复 |
| 重复 | 双击、重复请求、重复提交和幂等 |

详细基线见[通用测试基线](../../packages/skills/builtin/qa-core/references/test-design/universal-baseline.md)。

## 条件场景

只读取与当前功能匹配的一至三个模式。

| 功能信号 | 常见补充 |
| --- | --- |
| 账号与会话 | 邀请、验证、重置、会话刷新和角色变化 |
| 表单与导航 | 自动填充、输入法、校验时机、草稿和多标签页 |
| 流程与状态 | 并发、冲突、撤销、补偿和部分完成 |
| 文件与批量 | 中断、重试、部分失败、取消和导出 |
| 异步与集成 | 重复、乱序、漏投、死信和最终一致性 |
| 搜索与列表 | 组合筛选、分页、排序和陈旧索引 |
| 配置与发布 | 开关、灰度、migration、旧客户端和回滚 |
| 数据与隐私 | 生命周期、导出、删除、保留和恢复 |

完整扩展目录见[功能风险扩展](../../packages/skills/builtin/qa-core/references/test-design/feature-patterns.md)。

## 源码与运行

有源码时先读取 AGENTS、README、清单、现有测试和配置，再定位目标功能相关实现。

用户要求自动测试时，优先复用已有启动和测试命令。服务需要等待健康检查或明确就绪信号。测试数据和进程必须清理。

源码行为只作为观察。源码与需求或契约冲突时保留差异，不静默采用实现。

详细步骤见[源码与本地运行发现](../../packages/skills/builtin/qa-core/references/project-discovery.md)。

## 可维护代码

| 方面 | 要求 |
| --- | --- |
| 结构 | 一个测试表达一个业务行为，复杂流程拆成业务步骤 |
| 复用 | 使用现有 fixture、页面对象、API 客户端和数据工厂 |
| 类型 | 遵守项目严格类型和静态检查 |
| 注释 | 公共辅助说明用途和约束，复杂流程说明准备、操作、断言和清理 |
| 断言 | 验证用户结果、契约字段、数据变化或业务状态 |
| 清理 | 失败时也清理数据，并分别保留测试和清理错误 |

简单用例不写逐行注释。详细规范见[生成代码质量](../../packages/skills/builtin/qa-core/references/generated-code-quality.md)。

## 专项边界

性能、安全、可访问性和兼容性需要独立范围、指标和证据。

- 功能 smoke 不能替代 LCP、CLS 和 INP 性能验收。
- axe 等自动扫描不能证明 WCAG 2.2 完整合规。
- 普通权限验证不能替代 ASVS 或 WSTG 安全审计。
- 多浏览器 smoke 不能替代完整兼容性矩阵。
