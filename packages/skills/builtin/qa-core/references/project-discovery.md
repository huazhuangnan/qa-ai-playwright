# 源码与本地运行发现

用户要求读取源码、启动应用或自动测试时，按本参考定位最小工程信息。源码表达当前实现，仍不能代替业务需求。

## 读取顺序

1. 项目 `AGENTS.md`、README 和运行说明。
2. 语言清单、锁文件、脚本和依赖管理方式。
3. 现有测试、测试配置、fixtures 和 CI 命令。
4. 需求、OpenAPI、配置和环境变量说明。
5. 与目标功能相关的路由、页面、组件、处理器、schema 和数据层。
6. 只有影响结论时再读取相邻实现和依赖。

先按文件名、路由、符号和关键字定位。不要默认读取整个仓库、构建产物、依赖目录或大型生成文件。

## 工程识别

| 工程 | 优先检查 |
| --- | --- |
| Node/TypeScript | `package.json` 脚本、pnpm workspace、lockfile、Playwright/Vitest 配置、源码入口 |
| Python | `pyproject.toml`、requirements、pytest 配置、`conftest.py`、应用入口 |
| 容器 | Compose、镜像启动命令、端口映射、健康检查和数据卷 |
| 其他语言 | 构建清单、Makefile、运行文档和已有 CI |

已有测试优先于新建测试项目。现有 fixture 和启动脚本优先于重新实现。

## 源码证据

| 位置 | 可提取信息 |
| --- | --- |
| 路由和入口 | 页面、接口、跳转和中间件 |
| 表单和组件 | 字段、必填、状态和用户反馈 |
| 校验和 schema | 类型、边界、默认值和错误结构 |
| 认证和权限 | 登录、角色、资源归属和拒绝路径 |
| 数据访问层 | 唯一性、状态、事务、迁移和副作用 |
| 配置和功能开关 | 环境差异、默认值和启用条件 |
| 现有测试 | 已覆盖行为、fixture、数据隔离和运行入口 |

源码观察写入“依据或观察”，需求或契约写入“已确认”。
行为冲突时保留双方来源，不静默采用实现。

## 变更范围

| 变更位置 | 首选验证 |
| --- | --- |
| 页面、组件或表单 | 目标 UI 功能及相关 E2E |
| 路由、中间件或认证 | API 权限、会话和关键用户链路 |
| schema、校验或错误映射 | 契约、边界和错误响应 |
| 数据层或 migration | 持久化、回滚、旧数据和隔离 |
| 共享 fixture 或客户端 | 受影响测试集及稳定性 |
| 配置、依赖或启动入口 | 健康检查、smoke 和相关集成 |

## 启动发现

按以下顺序选择启动方式：

1. 项目文档或 AGENTS 给出的测试命令。
2. 现有测试配置中的 `webServer`、fixture 或服务启动脚本。
3. 清单中的 `dev`、`start`、`serve` 或等价脚本。
4. Compose、Makefile、task runner 或容器配置。
5. 框架入口和已有日志，仅在以上缺失时推断。

优先使用项目脚本。命令、环境和工作目录来自项目实际配置。
`webServer` 的复用开关按项目配置和 CI 环境处理。CI 默认使用独立服务和端口。

启动前检查：

- 地址和端口。
- 运行时版本与已安装依赖。
- 数据库、缓存、消息系统和外部依赖。
- migration、seed、数据目录和重置方式。
- 写保护、功能开关和外部副作用。
- 就绪地址、健康检查或可观察启动日志。

## 自动执行

用户明确要求自动测试时，可以在本地或已授权测试环境执行：

- 复用现有测试项目和命令。
- 启动缺少的服务，等待明确就绪信号。
- 先运行最小目标用例，再按结果扩大范围。
- 记录命令、工作目录、环境标识、退出码、耗时和进程日志位置。
- 失败或完成后停止本次启动的进程并执行清理。

以下情况先停止并向用户集中说明：

- 需要生产写入、真实资金或外部消息。
- 需要接管个人会话、真实客户数据或高权限凭证。
- migration、seed 或 reset 可能破坏非隔离数据。
- 依赖或服务缺失，继续只能下载、购买或扩大权限。

## 数据库与数据

- 优先内存库、临时文件、独立测试库或项目已有隔离容器。
- 数据创建后立即登记 LIFO 清理。
- 进程失败也必须尝试清理数据和服务。
- 迁移失败、seed 失败和测试失败分别报告。
- 不把开发数据、生产快照或真实客户数据复制到报告。

## 生成与执行

- 从源码识别候选场景，从需求或契约确认预期。
- 复用现有 fixture、页面对象、API 客户端和唯一数据方式。
- 自动生成测试前先预览并确认范围。
- 生成后先检查 diff，再运行选定目标。
- 服务启动失败时不伪造测试通过。
- 没有源码或启动条件时，仍可交付计划、候选用例和阻塞说明。
