# 通用测试基线

每个功能先应用本基线。基线帮助发现候选用例，不替代需求、契约或业务确认。

基线是思考框架，不是必须照抄的清单。模型需要结合业务目标、风险、源码、页面观察和执行条件判断适用性，并说明不适用项的原因。

- 资料明确时形成候选或正式用例。
- 资料冲突时并列来源并标待确认。
- 没有资料依据时只能提出建议。
- 低风险且无业务依赖的候选可以主动排除，不输出机械清单。

## 最小覆盖

| 维度 | 至少考虑 |
| --- | --- |
| 入口 | 前置状态、可达入口、深链接和返回 |
| 主流程 | 一条最小合法路径和必要业务结果 |
| 必填输入 | 缺失、空值、清空和默认值 |
| 非法输入 | 类型、格式、长度、边界和服务器校验 |
| 权限 | 未登录、无权限、角色和资源归属 |
| 状态 | 前置是否满足、成功转换和不可逆结果 |
| 持久化 | 页面或响应之外的数据是否真的改变 |
| 副作用 | 关联记录、通知、审计和清理 |
| 失败 | 空状态、加载失败、依赖失败和用户恢复 |
| 重复 | 双击、重复请求和重复提交 |
| 恢复 | 刷新、返回、重新进入和部分完成 |
| 可观察性 | 页面、响应、数据、日志和关联 ID |

## 默认测试顺序

1. 一条最小成功路径。
2. 一条必填或非法输入。
3. 一条未登录或无权限访问。
4. 一条数据真实持久化或副作用检查。
5. 一条失败、重试或恢复路径。
6. 只在确有风险时补重复、并发、导航和兼容。

订单、支付、权限、删除等高风险功能继续使用匹配的扩展模式。

## 专项触发

| 信号 | 单独确认 |
| --- | --- |
| 认证、权限、外部输入、上传或敏感数据 | 安全范围、威胁模型、ASVS/WSTG 条款 |
| 大列表、慢页面、复杂交互或明确耗时 | LCP、CLS、INP、设备和网络条件 |
| 键盘、焦点、标签、错误提示或放大 | WCAG 2.2 成功标准和人工验证 |
| 浏览器、设备、屏幕或系统版本 | 兼容性矩阵 |

普通功能测试不能替代上述专项验收。

## 按层拆分

| 层级 | 重点 |
| --- | --- |
| UI | 用户动作、可见状态、表单反馈和导航恢复 |
| API | method、认证、输入、状态码、schema 和副作用 |
| 集成 | 真实依赖、部分失败、重试和最终一致性 |
| 数据 | 唯一性、事务、migration、回滚和清理 |

同一断言不在各层重复。UI 用例验证用户结果，API 用例验证协议和副作用，E2E 只覆盖关键组合链路。

## 预期规则

- 需求或契约明确时写精确断言。
- 源码或页面行为只作为观察。
- 缺少业务规则时写候选和待确认项。
- 空泛的“正常”“符合预期”不能作为断言。
- 通过必须来自实际执行证据。
- 不照搬风险目录。先判断“为什么这个场景可能失败”，再决定是否保留。

## Token 规则

- 默认只读本基线。
- 功能匹配时再读扩展目录中的一至三个章节。
- 不把未匹配的候选全部输出。
- 默认输出 5 至 10 个高价值场景，更多内容按优先级分组。
- 不复述标准模板已经包含的字段。
- 已有用例覆盖同一行为时只检查缺口。
