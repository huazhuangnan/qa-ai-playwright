# QA 公共执行边界

所有 QA 任务共用本参考。专业 Skill 不重复这些规则。

## 输入

- 先读项目 AGENTS.md、需求、契约、现有测试和环境说明。
- 浏览器测试先检测并复用用户已有的兼容浏览器。确认缺失后才下载。用户指定浏览器时按其选择处理。使用独立上下文，不接管日常浏览器的登录状态。
- 项目使用自定义路径的系统浏览器时，通过 `QA_BROWSER_EXECUTABLE_PATH` 指定可执行文件。Chrome 和 Edge 指定对应通道。系统 Chromium 的通道留空。本机绝对路径不写入公共模板默认值。
- 区分已确认规则、实际观察和待确认假设。
- 只追问会影响执行的缺口。
- 生成测试时为每个用例说明业务目标、关键前置条件和非显然断言。辅助函数按语言习惯使用 TSDoc 或 docstring，避免逐行复述代码。
- 控制 token 用量。先按索引、路径或关键字定位，再读取相关章节。限制日志和工具输出，按需展开原始错误与上下文。
- 复用已确认的结果，避免重复读取和执行。完成任务所需的验证和证据不能省略。

## 配置

- `QA_ENV` 选择 `.env.<环境>`。
- `UI_BASE_URL` 和 `API_BASE_URL` 分别指向页面和接口。
- `BASE_URL` 只作兼容回退。
- 进程环境和 CI 配置优先于本地文件。
- 凭证使用环境变量、CI secret 或密钥系统。
- TypeScript 依赖使用 pnpm 与 `pnpm-lock.yaml`。
- 项目脚本使用 Bun。Playwright 和原生 Node 模块使用 Node。

## 敏感信息检查

- 读取资料前确认任务范围和敏感级别。优先使用合成数据或已脱敏样例，不要求用户在对话中提供凭证或真实客户数据。
- 凭证由用户放入被 Git 忽略的本地 `.env`、进程环境、CI secret 或密钥系统。密钥系统须通过项目机制注入环境变量，模板不直接连接密钥系统。
- 只询问变量名或密钥位置，不在对话、日志或产出中记录凭证原值。不要在命令参数中传入凭证。
- 执行前确认环境、最小权限账号和数据范围。发现生产环境或真实客户数据时暂停，先确认授权和可用的脱敏测试数据。
- 限制日志和工具输出。请求、响应、错误、截图、视频、Trace 和登录态都可能包含敏感信息，不能默认安全。
- 分享证据前检查并移除凭证、个人信息和业务敏感字段。保留排查所需的最小信息。无法确认已安全处理时，不分享原始证据，说明限制并请求安全的替代资料。
- 此检查是人工和 AI 的执行规则，不代表工具已自动扫描、脱敏或保证无泄露。原始证据按项目授权范围保存，并限制访问和保留期限。

## 跨平台

- 按项目支持的平台处理路径、盘符、分隔符和包含空格的目录。路径断言使用与实际结果一致的绝对或相对语义。
- 启动外部程序时区分可执行文件与 Windows `.cmd`、`.bat` 脚本。安全传递参数，保留失败时的原始错误。
- 按变更范围验证目标平台。未实际运行的平台标明未验证。

## 写入与清理

- 写入前确认环境、角色、数据范围和授权。
- 生产写入默认禁止。
- 测试数据使用唯一标识和隔离所有者。
- 数据创建后立即登记清理，按 LIFO 执行。
- 原测试错误和清理错误分别报告。

## 用例质量与迭代

- 用例使用稳定 ID，并关联需求、规则、风险、自动化实现和运行记录。
- 步骤使用单一动作。预期必须写成可观察信号，至少包含状态、数据、页面状态、响应字段或日志关联 ID 之一。
- 关键用例保留最近结果、flaky 状态、失败归因、变更触发条件和复测关联。
- 需求、契约、代码、环境或数据变化触发影响分析。先更新测试计划和追踪关系，再修改用例或实现。
- 重试用于确认稳定性，不用于制造通过。重试后通过仍记录 flaky，并进入后续治理。
## 证据与结论

- 只报告实际执行。
- 区分通过、失败、跳过、重试后通过和未执行。
- 跳过不计为覆盖。
- 失败证据先脱敏，再进入报告或对话。
- 没有证据时不宣称业务验收通过。

## 文档

- 输入资料写 `docs/qa/inputs/`。
- 已确认任务写 `docs/qa/tasks/`。
- 计划和用例写 `docs/qa/generated/`，按[测试设计](test-design.md)处理。
- 缺陷和执行报告写 `docs/qa/generated/`，按[失败分析](triage.md)处理。
- 外部资料归档和静态导出按[资料处理](documents.md)执行。
