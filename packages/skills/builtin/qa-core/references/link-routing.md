# 链接输入分类与路由

用户只提供链接时，先判断链接提供的是页面、契约、资料还是入口。一个链接可以同时属于多种类型。

## 分类

| 类型 | 常见信号 | 首要用途 | 路由 |
| --- | --- | --- | --- |
| Web 应用或页面 | HTML、前端路由、登录页、重定向 | 用户可见行为、会话和 E2E | [Web 功能测试](web-testing.md) |
| OpenAPI JSON/YAML | `application/json`、`yaml`、`openapi`、`swagger` 根字段 | 接口契约、schema 和认证 | [API 与服务测试](api-testing.md) |
| Swagger UI / Redoc | 渲染后的契约文档、定义文件引用 | 读取并取得原始契约 | [API 与服务测试](api-testing.md) |
| API 文档页面 | 接口目录、请求响应和授权说明 | 提取目标操作的规则和来源 | [API 与服务测试](api-testing.md) |
| PRD、Wiki 或需求 | 角色、流程、验收标准和版本信息 | 业务理解和测试设计 | [业务理解](business-guide.md)、[测试设计](test-design.md) |
| 代码、Issue、测试报告 | 仓库、提交、缺陷、运行结果 | 现状、约束和回归证据 | [源码与本地运行发现](project-discovery.md)，不当作正式需求 |
| 文件下载 | 附件、压缩包、规范或样例 | 读取后按内容重新分类 | 本地文件分析 |
| 未知或不可访问 | 401、403、404、重定向、登录墙、脚本页面 | 记录限制和最小补充项 | 继续可做的分析与设计 |

本地地址、`file://` 页面、源码目录和可运行仓库按源码入口处理。先定位启动命令和现有测试，再从页面或接口验证行为。

## 扩展输入

| 输入 | 当前处理 | 限制 |
| --- | --- | --- |
| Postman Collection | 提取请求、变量、认证和样例 | 不自动视为完整契约 |
| HAR 或网络记录 | 提取实际请求、响应和资源关系 | 属于观察证据，可能包含敏感信息 |
| GraphQL schema | 提取类型、字段、查询和认证 | 业务规则、权限和错误语义仍需资料 |
| AsyncAPI 或 Webhook | 设计事件、重试、幂等和最终一致性用例 | 需要触发方式、签名、接收端和证据通道 |
| gRPC proto | 提取服务、消息和方法定义 | 没有专属生成器，按项目现有工具执行 |
| SOAP 或 WSDL | 提取操作、消息和错误结构 | 没有专属生成器，按项目现有工具执行 |
| PDF、Office 或截图资料 | 提取相关文字、表格和版本 | 扫描件识别可能不完整，以原文件为准 |
| 仓库、Issue 或测试报告 | 获取现状、约束和历史证据 | 不自动等同于正式需求或验收标准 |

## 判断顺序

1. 先读取 HTTP 状态、内容类型和可见标题。
2. 结构化内容优先识别 OpenAPI 根字段、版本和 `paths`。
3. 渲染页面若提示 API 文档，继续查找原始定义或同源下载入口。
4. 普通网页按 Web 应用处理，检查重定向、登录墙、iframe 和多域名。
5. 只有页面文字时，区分观察、推断和待确认规则。

不要只按 URL 后缀判断类型。不要一次抓取整站，只访问任务相关的链接和子资源。

## 组合链接

- Web 链接与 OpenAPI 同时存在时，分别读取。
- 契约用于定义预期，Web 应用用于验证实际行为。
- 两者不一致时保留差异，不静默采用其中一方。
- 只有 Web 链接时，可从页面网络请求发现候选 API。
- 发现的接口按实际观察处理，不能自动当作正式契约。
- 只有 OpenAPI 时，可以生成接口测试，但不能据此宣称 UI 或 E2E 已覆盖。

## 安全边界

- OpenAPI 的 `Try it out`、Swagger 控制台和 API 文档页面中的执行按钮都可能调用真实服务。
- 调用前确认环境、认证、写操作和清理方式。
- 生产环境默认只做只读探索。
- 登录墙后的链接需要最小权限测试账号或用户已有的隔离会话。
- 不接管日常浏览器会话，不记录凭证原值。

## 交付结果

预览至少说明：

| 项目 | 内容 |
| --- | --- |
| 输入类型 | 识别到的页面、契约、资料或未知类型 |
| 依据 | URL、状态、标题、契约版本和读取时间 |
| 可执行范围 | 当前能验证的行为 |
| 组合关系 | 页面和契约是否互相支持或存在差异 |
| 缺口 | 环境、账号、预期、生命周期、清理和授权 |
| 后续路由 | 页面、API、业务分析及语言实现 |
