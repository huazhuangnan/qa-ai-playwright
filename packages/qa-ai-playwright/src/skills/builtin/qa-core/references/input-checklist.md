# QA 输入清单

按当前任务选择必要资料。不要一次索取无关信息。
缺少资料时，合并成一个“请补充”清单。说明每项用途和可接受格式。
不依赖缺口的部分可以先完成。
无法确认的预期应标为“待确认”。不能从当前产品行为倒推。
- 用户已提供链接时优先调用现有网页或浏览器能力读取。
- 不重复索取 Codex 已可访问的页面内容。
- 外部文档由 `qa-docs` 负责相关性判断和精简归档。

## 通用资料

- 需求、验收标准或已确认测试计划的链接与版本。
- 本次覆盖范围、不覆盖项和允许执行的操作。
- 目标环境标识，例如 `dev` 或 `stg`，及允许写入的测试租户。
- 当前环境文件，例如 `.env.dev` 或 `.env.stg`。
- `docs/qa/inputs/input-index.md` 中登记的全部变量名与来源。
- 服务入口、认证、角色、租户、资源、数据、清理和功能开关等实际配置需求。
- 用户角色、权限边界和资源归属。
- 测试账号标识、所属租户、状态和到期时间。
- 测试数据的创建、重置、隔离和清理负责人。
- 可观察的业务预期、证据类型和完成条件。
- 目标交付物，例如测试计划、手工用例、自动化代码或缺陷报告。
- 语言模板版本、依赖锁文件和测试标签。
- API 测试是否为发布门禁，以及门禁失败时使用的执行环境。
- 时间、浏览器、设备、平台或其他项目约束。

没有明确测试环境时，不要猜测地址。
不要默认把生产环境当作测试目标。

## API 与集成测试

- API 文档链接、OpenAPI/Swagger 定义或接口说明。
- 请求与响应的脱敏 JSON 样例。
- 基础地址、方法、路径、必填字段和请求头。
- 认证方式、角色范围和获取测试身份的方式。
- 成功、业务错误和系统错误的状态码及业务契约。
- 创建、更新、删除后的可观察副作用。
- 幂等、重试、超时、限流和异步完成规则。
- 依赖服务、数据库、消息系统和测试替身边界。

优先请求文档链接或契约文件。
文档可以提供 URL、项目内路径或 OpenAPI JSON/YAML 文件。
没有文档时，再请求最小范围的脱敏请求和响应样例。

## UI 与 E2E 测试

- 起始地址、用户旅程和结束条件。
- 各角色进入流程所需的前置状态。
- 页面可观察结果、持久化结果和下游影响。
- 测试数据准备、账号复用限制和清理方式。
- 目标浏览器、设备、视口和会话状态。
- 是否允许测试环境中的写入或消息发送。

## 单元与集成测试

- 被测函数、类或模块及其公开契约。
- 业务项目已有测试框架、fixture 和运行命令。
- 输入边界、异常类型和关键副作用。
- 外部依赖使用真实服务还是测试替身。
- 依赖准备、状态重置和资源清理顺序。

## 失败分析

- 需求预期与实际结果的对照。
- 最小复现步骤、实际命令和首次失败时间。
- 环境、构建版本、浏览器或运行时版本。
- 脱敏后的错误、日志、截图、Trace 或网络记录。
- 最近变更、已知环境问题和数据前置条件。

## 凭证与数据安全

- 不要求用户把密码、Token、Cookie、私钥或真实客户数据粘贴到对话。
- 只记录凭证的环境变量名、CI secret 名称或密钥系统位置。
- 本地调试使用被 Git 忽略的 `.env`。提交可复用的 `.env.example`，不提交真实值。
- 进程环境变量和 CI secrets 覆盖 `.env`，用于共享环境与流水线。
- 需要执行时，请用户自行在本地环境或密钥系统中设置值，再告知变量名和使用范围。
- 测试账号优先使用专用邮箱、手机号或租户。避免使用真实个人信息。
- 使用专用测试环境、专用账号和最小权限。
- 优先使用短期凭证。明确有效期和资源范围。
- 不把认证状态、敏感响应或含个人数据的报告提交到仓库。
- 使用真实数据前先脱敏。需要保留时说明期限和访问范围。
- 没有明确授权时，不执行生产写入或外部消息发送。
- 生产写入必须额外设置 `QA_ALLOW_PRODUCTION_WRITES=true`，并记录授权范围。
