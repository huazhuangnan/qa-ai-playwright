## 测试数据

| 用户 | 用户名 | 密码 | 角色 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `demo1234` | `admin` |
| 成员 A | `alice` | `demo1234` | `member` |
| 成员 B | `bob` | `demo1234` | `member` |

- 每次测试运行使用同一个临时 SQLite 数据库，启动时重建。
- 测试数据使用唯一前缀。
- 浏览器测试使用独立 context。
- 测试数据按用例清理。临时数据库保留至下次运行重建。

## 分层

| 层级 | 验证重点 | 入口 |
| --- | --- | --- |
| QA 工具 | 环境、fixture 和测试辅助逻辑 | 各项目运行器 |

| UI | 表单与可观察页面行为 | Playwright 浏览器 |

| 非功能 | 可访问性、移动视口、控制台错误 | Playwright |

## 准入

- 依赖安装完成。
- 类型检查通过。
- 临时数据库可创建和清理。
- 开发服务可启动。

## 退出

- P0、P1 用例无最终失败。
- 跳过用例有原因和负责人。
- 失败证据已脱敏。
- 执行报告记录实际命令和结果。
- 清理结果明确。

## API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `POST` | `/api/auth/login` | 登录 |
| `POST` | `/api/auth/logout` | 退出 |
| `GET` | `/api/auth/me` | 当前用户 |
| `GET` | `/api/users` | 负责人选项 |
| `GET` | `/api/tickets` | 查询工单 |
| `POST` | `/api/tickets` | 创建工单 |
| `GET` | `/api/tickets/:id` | 工单详情 |
| `PATCH` | `/api/tickets/:id` | 更新工单 |
| `DELETE` | `/api/tickets/:id` | 删除工单 |
| `GET` | `/api/tickets/:id/comments` | 评论列表 |
| `POST` | `/api/tickets/:id/comments` | 添加评论 |
| `GET` | `/api/tickets/:id/audit` | 审计记录 |

## 风险

| 风险 | 缓解 |
| --- | --- |
| SQLite 文件被并行测试共享 | 固定单 worker；每次运行重建数据库 |
| 会话泄漏 | 每个测试使用新的 browser context |
| 页面定位器依赖样式 | 使用 role、label 和可见文本 |
| 状态流转规则漂移 | 状态机由单元和 API 测试共同约束 |
